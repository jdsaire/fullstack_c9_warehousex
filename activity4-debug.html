Corrected Application Code (Submission Item S4 / Prompt P5)

Course 9 Capstone prompt P5 requires the final debugged and corrected application code. Below is the direct progression from the baseline course snippet (Activity 4 Step 2) through preliminary guard clauses (Activity 4 Step 3) to the production-ready resilient implementation with SQLite state synchronization.

Baseline · Non-Resilient (Step 2) 
public void ProcessOrder(Order order)
{
    var product = db.Products.Find(order.ProductId);
    product.Stock -= order.Quantity;
    Console.WriteLine($"Order {order.Id} processed.");
}
Identified Vulnerabilities:
  • Null Reference Crash: If Find returns null, accessing product.Stock throws an unhandled NullReferenceException.
  • Negative Inventory: No check that Stock >= Quantity; overdrafts produce negative stock balances.
  • Unvalidated Boundaries: Zero or negative order quantities (Quantity <= 0) bypass validation.
  • No State Persistence: In-memory mutation is not synchronized back to persistent database storage.
Debugged · Submission S4 (Prompt P5) 
public void ProcessOrder(Order order)
{
    // 1. Guard against null order payload
    if (order == null)
        throw new ArgumentNullException(nameof(order), "Order payload cannot be null.");

    // 2. Guard against non-positive order quantity
    if (order.Quantity <= 0)
        throw new InvalidOrderQuantityException(order.Id, order.Quantity);

    // 3. Guard against non-existent product in catalog
    var product = db.Products.Find(order.ProductId);
    if (product == null)
        throw new ProductNotFoundException(order.ProductId);

    // 4. Guard against insufficient stock overdraft
    if (product.Stock < order.Quantity)
        throw new InsufficientStockException(order.ProductId, order.Quantity, product.Stock);

    // 5. Deduct stock and persist to database
    product.Stock -= order.Quantity;
    db.Products.UpdateStock(product.Id, product.Stock);

    Console.WriteLine($"Order {order.Id} processed.");
}
Defensive Resilience Features:
  • Domain Exception Hierarchy: Throws specific typed exceptions with contextual error data.
  • Complete Boundary Protection: Validates order nullability, positive quantity, and stock limits.
  • Data Store Persistence: Invokes db.Products.UpdateStock to guarantee SQLite database integrity.
  • Zero Uncaught Crashes: Compatible with structured TryProcessOrder wrapper returning status codes.

Step 3 Preliminary Suggested Guard Clauses Analysis

Course 9 Activity 4 Step 3 introduces two preliminary guard clauses. While they successfully identify the need for null checks and stock validation, our final implementation expands upon them by introducing typed domain exceptions and input boundary validation:

Course Step 3 Generic Suggestions: 
if (product == null)
    throw new Exception("Product not found.");
if (product.Stock < order.Quantity)
    throw new Exception("Insufficient stock.");
Limitation: Throws generic base Exception; lacks payload validation, edge-case handling, and persistence.
Final Enterprise Architecture Improvements:
  • Replaces generic Exception with typed ProductNotFoundException and InsufficientStockException.
  • Adds Guard 1 for null order payload (ArgumentNullException).
  • Adds Guard 2 for zero/negative quantity (InvalidOrderQuantityException).
  • Applies atomic SQLite database persistence via UpdateStock.

Domain Exception Hierarchy & Error Architecture

To distinguish business rule rejections from system infrastructure faults, WarehouseX establishes a structured exception hierarchy under WarehouseException.

Exception Type Base Class Error Code Trigger Condition Contextual Payload
ProductNotFoundException WarehouseException PRODUCT_NOT_FOUND db.Products.Find(id) == null ProductId
InsufficientStockException WarehouseException INSUFFICIENT_STOCK product.Stock < order.Quantity ProductId, RequestedQuantity, AvailableStock
InvalidOrderQuantityException WarehouseException INVALID_QUANTITY order.Quantity <= 0 OrderId, Quantity
InvalidOrderException WarehouseException INVALID_ORDER Corrupted or malformed order Error explanation string
ArgumentNullException SystemException NULL_ORDER order == null Parameter name nameof(order)

Host Stability Wrapper: `OrderService.TryProcessOrder`

To prevent unexpected application crashes during batch order fulfillment (Course Focus Area F4 / Strategy ST2), TryProcessOrder wraps order operations and returns an immutable OrderProcessingResult model: 

public static OrderProcessingResult TryProcessOrder(WarehouseDbContext db, Order order, Action<string>? logAction = null)
{
    if (order == null)
        return OrderProcessingResult.Failed(0, 0, 0, "NULL_ORDER", "Order payload cannot be null.");

    try
    {
        ProcessOrderDebugged(db, order, logAction);
        var product = db.Products.Find(order.ProductId);
        return OrderProcessingResult.Completed(order.Id, order.ProductId, order.Quantity, product?.Stock ?? 0);
    }
    catch (ProductNotFoundException ex)
    {
        return OrderProcessingResult.Failed(order.Id, order.ProductId, order.Quantity, "PRODUCT_NOT_FOUND", ex.Message);
    }
    catch (InsufficientStockException ex)
    {
        return OrderProcessingResult.Failed(order.Id, order.ProductId, order.Quantity, "INSUFFICIENT_STOCK", ex.Message);
    }
    catch (InvalidOrderQuantityException ex)
    {
        return OrderProcessingResult.Failed(order.Id, order.ProductId, order.Quantity, "INVALID_QUANTITY", ex.Message);
    }
    catch (Exception ex)
    {
        return OrderProcessingResult.Failed(order.Id, order.ProductId, order.Quantity, "UNEXPECTED_ERROR", ex.Message);
    }
}
